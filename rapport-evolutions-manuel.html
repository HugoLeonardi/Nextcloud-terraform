1. Adresse IP Élastique (Elastic IP)

Une Elastic IP est une adresse IPv4 publique fixe allouée sur le compte AWS. Sans elle, l'IP de l'instance EC2 change à chaque redémarrage, rendant Nextcloud inaccessible. Toute l'opération se fait dans la console AWS, sans toucher au serveur.

Étape 1 – Allouer une Elastic IP Console AWS

  • 1
    Ouvrir la Console AWS et se rendre dans :
    EC2 › Réseau et sécurité › Adresses IP élastiques
  • 2
    Cliquer sur « Allouer une adresse IP élastique ».
  • 3
    Laisser les paramètres par défaut (pool d'adresses Amazon). Cliquer sur « Allouer ». Une nouvelle adresse IPv4 publique apparaît dans la liste.

Étape 2 – Associer l'Elastic IP à l'instance EC2 Console AWS

  • 1
    Sélectionner l'adresse nouvellement allouée dans la liste.
  • 2
    Cliquer sur « Actions » puis « Associer une adresse IP élastique ».
  • 3
    Dans le champ « Instance », sélectionner l'instance EC2 Nextcloud (nextcloud-sio-server).
  • 4
    Cliquer sur « Associer ». L'ancienne IP dynamique de l'instance est immédiatement remplacée par l'Elastic IP.
✓ Nextcloud est maintenant accessible via l'Elastic IP. Cette adresse reste la même même après un arrêt/redémarrage de l'instance.

Étape 3 – Mettre à jour les trusted_domains Nextcloud SSH

Nextcloud refuse les connexions depuis un domaine ou une IP non déclarée. Après changement d'IP, il faut mettre à jour la configuration.

Se connecter en SSH à l'instance
ssh -i nextcloud-key.pem ec2-user@<ELASTIC_IP>
Mettre à jour le trusted_domain dans Nextcloud
# Ajouter l'Elastic IP comme domaine de confiance
sudo -u apache php /var/www/html/nextcloud/occ \
  config:system:set trusted_domains 1 \
  --value="<ELASTIC_IP>"
⚠ Une Elastic IP non associée à une instance est facturée (~0,005 $/heure). Penser à la libérer avec terraform destroy ou depuis la console si l'infrastructure est supprimée.

2. Certificat TLS/SSL avec Let's Encrypt

Let's Encrypt délivre des certificats TLS gratuits et automatiquement renouvelables. L'outil Certbot s'occupe d'obtenir le certificat et de configurer Apache. Cette procédure se fait entièrement en SSH sur l'instance EC2. Un nom de domaine pointant vers l'Elastic IP est obligatoire.

Prérequis Avant de commencer

ConditionComment vérifier
Elastic IP associée à l'instance Console AWS → EC2 → Adresses IP élastiques
Enregistrement DNS de type A configuré nslookup nextcloud.mondomaine.fr → doit retourner l'Elastic IP
Port 80 ouvert dans le Security Group EC2 Console AWS → EC2 → Groupes de sécurité → nextcloud-sio-sg-ec2
Port 443 ouvert dans le Security Group EC2 Même vérification — règle entrante HTTPS 0.0.0.0/0

Étape 1 – Configurer l'enregistrement DNS Registrar

  • 1
    Se connecter à l'interface du registrar du domaine (OVH, Gandi, Cloudflare…).
  • 2
    Créer un enregistrement DNS de type A :
    ChampValeur
    TypeA
    Nom / Sous-domainenextcloud (ou @ pour le domaine racine)
    Valeur<ELASTIC_IP>
    TTL300 (5 min pour les tests)
  • 3
    Attendre la propagation DNS (quelques minutes à 1 heure). Vérifier avec : 
    nslookup nextcloud.mondomaine.fr

Étape 2 – Vérifier le port 443 dans le Security Group Console AWS

  • 1
    Aller dans : EC2 › Groupes de sécurité › nextcloud-sio-sg-ec2
  • 2
    Onglet « Règles entrantes » → vérifier qu'une règle HTTPS (port 443) existe. Si absente : cliquer sur « Modifier les règles entrantes » → « Ajouter une règle » → Type : HTTPS, Source : 0.0.0.0/0 → « Enregistrer ».

Étape 3 – Installer Certbot et obtenir le certificat SSH

Se connecter en SSH
ssh -i nextcloud-key.pem ec2-user@<ELASTIC_IP>
Installer Certbot
# Installation de Certbot et son module Apache
sudo dnf install -y certbot python3-certbot-apache
Obtenir le certificat et configurer Apache automatiquement
# Certbot contacte Let's Encrypt, prouve la propriété du domaine
# et configure Apache (VirtualHost HTTPS + redirection HTTP→HTTPS)
sudo certbot --apache \
  --email admin@mondomaine.fr \
  --domain nextcloud.mondomaine.fr \
  --agree-tos \
  --redirect \
  --non-interactive

Certbot va :

  • Créer un défi HTTP-01 pour prouver la propriété du domaine
  • Obtenir le certificat auprès de Let's Encrypt
  • Modifier la configuration Apache pour activer HTTPS
  • Ajouter une redirection automatique HTTP → HTTPS
  • Placer les certificats dans /etc/letsencrypt/live/nextcloud.mondomaine.fr/
Vérifier que Apache redémarre bien avec le certificat
sudo systemctl status httpd

Étape 4 – Activer le renouvellement automatique SSH

Les certificats Let's Encrypt expirent au bout de 90 jours. Certbot installe un timer systemd qui renouvelle automatiquement avant expiration.

# Activer le timer de renouvellement automatique
sudo systemctl enable --now certbot-renew.timer

# Vérifier que le timer est actif
sudo systemctl status certbot-renew.timer

# Tester le renouvellement à blanc (sans réellement renouveler)
sudo certbot renew --dry-run

Étape 5 – Mettre à jour la configuration Nextcloud SSH

Nextcloud doit être informé du nouveau protocole et du nom de domaine.

# Indiquer à Nextcloud d'utiliser HTTPS pour générer ses URLs
sudo -u apache php /var/www/html/nextcloud/occ \
  config:system:set overwriteprotocol --value="https"

# Ajouter le nom de domaine aux domaines de confiance
sudo -u apache php /var/www/html/nextcloud/occ \
  config:system:set trusted_domains 2 \
  --value="nextcloud.mondomaine.fr"
✓ Nextcloud est maintenant accessible en HTTPS. Tester dans un navigateur : https://nextcloud.mondomaine.fr — le cadenas vert doit apparaître.
⚠ Let's Encrypt limite à 5 certificats par domaine par semaine. Pour les tests, ajouter le flag --staging à la commande certbot (le certificat sera invalide mais la limite ne s'applique pas).

3. Supervision avec Amazon CloudWatch

CloudWatch collecte des métriques, déclenche des alarmes et envoie des notifications. La procédure se déroule en deux parties : installation de l'agent CloudWatch sur l'EC2 (via SSH) puis création des alarmes et du tableau de bord dans la console AWS.

Partie A – Installer l'agent CloudWatch sur l'EC2 SSH

AWS collecte nativement le CPU et le réseau de l'EC2, mais pas la RAM ni l'espace disque. L'agent CloudWatch est nécessaire pour remonter ces métriques.

Se connecter en SSH
ssh -i nextcloud-key.pem ec2-user@<IP_EC2>
Installer l'agent CloudWatch
sudo dnf install -y amazon-cloudwatch-agent
Créer le fichier de configuration de l'agent
sudo tee /opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json << 'EOF'
{
  "metrics": {
    "namespace": "Nextcloud/System",
    "metrics_collected": {
      "mem": {
        "measurement": ["mem_used_percent"],
        "metrics_collection_interval": 60
      },
      "disk": {
        "measurement": ["disk_used_percent"],
        "resources": ["/"],
        "metrics_collection_interval": 60
      }
    }
  },
  "logs": {
    "logs_collected": {
      "files": {
        "collect_list": [
          {
            "file_path": "/var/log/userdata.log",
            "log_group_name": "/nextcloud/userdata",
            "log_stream_name": "{instance_id}"
          },
          {
            "file_path": "/var/log/httpd/nextcloud_error.log",
            "log_group_name": "/nextcloud/apache-errors",
            "log_stream_name": "{instance_id}"
          }
        ]
      }
    }
  }
}
EOF
Démarrer l'agent et l'activer au démarrage
# Charger la configuration et démarrer l'agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config \
  -m ec2 \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json \
  -s

# Activer le démarrage automatique
sudo systemctl enable amazon-cloudwatch-agent

# Vérifier que l'agent tourne
sudo systemctl status amazon-cloudwatch-agent
ℹ Les métriques mem_used_percent et disk_used_percent apparaissent dans CloudWatch sous le namespace Nextcloud/System après 1 à 2 minutes.

Partie B – Vérifier les droits IAM de l'EC2 Console AWS

L'agent CloudWatch a besoin de droits pour envoyer des métriques et des logs. Ces droits doivent être présents dans le rôle IAM attaché à l'instance.

  • 1
    Aller dans : IAM › Rôles › nextcloud-sio-ec2-role
  • 2
    Cliquer sur « Attacher des politiques ».
  • 3
    Rechercher et sélectionner la politique gérée CloudWatchAgentServerPolicy. Cliquer sur « Attacher les politiques ».
⚠ Sans ce rôle, l'agent CloudWatch ne peut pas envoyer de données et affichera des erreurs de type NoCredentialProviders dans ses logs.

Partie C – Créer un topic SNS pour les alertes email Console AWS

  • 1
    Aller dans : Simple Notification Service (SNS) › Rubriques › Créer une rubrique
  • 2
    Type : Standard. Nom : nextcloud-sio-alerts. Cliquer sur « Créer une rubrique ».
  • 3
    Dans la rubrique créée, cliquer sur « Créer un abonnement ». Protocole : Email. Point de terminaison : votre@email.fr. Cliquer sur « Créer un abonnement ».
  • 4
    Confirmer l'abonnement en cliquant sur le lien reçu par email. Sans cette confirmation, aucune alerte ne sera envoyée.

Partie D – Créer les alarmes CloudWatch Console AWS

Répéter la procédure suivante pour chaque alarme souhaitée.

  • 1
    Aller dans : CloudWatch › Alarmes › Créer une alarme
  • 2
    Cliquer sur « Sélectionner une métrique » et choisir la métrique selon le tableau ci-dessous.
  • 3
    Définir la condition (seuil), la période et le nombre de points de données.
  • 4
    Dans « Actions » : choisir « En alarme », puis sélectionner le topic SNS nextcloud-sio-alerts.
  • 5
    Donner un nom à l'alarme et cliquer sur « Créer une alarme ».
Alarme Namespace / Métrique Dimension Seuil Période
CPU EC2 élevé AWS/EC2 › CPUUtilization InstanceId = nextcloud-sio-server > 80 % 5 min × 2
RAM élevée Nextcloud/System › mem_used_percent InstanceId = nextcloud-sio-server > 85 % 5 min × 2
Disque plein Nextcloud/System › disk_used_percent path = /, InstanceId = … > 90 % 5 min × 1
CPU RDS élevé AWS/RDS › CPUUtilization DBInstanceIdentifier = nextcloud-sio-db > 70 % 5 min × 2
Espace RDS faible AWS/RDS › FreeStorageSpace DBInstanceIdentifier = nextcloud-sio-db < 5 Go (5 368 709 120 octets) 5 min × 1

Partie E – Créer un tableau de bord CloudWatch Console AWS

  • 1
    Aller dans : CloudWatch › Tableaux de bord › Créer un tableau de bord
  • 2
    Nommer le tableau de bord : Nextcloud-Supervision.
  • 3
    Ajouter des widgets un par un (bouton « + ») :
    WidgetTypeMétrique
    CPU EC2CourbeAWS/EC2 › CPUUtilization
    RAMJaugeNextcloud/System › mem_used_percent
    DisqueJaugeNextcloud/System › disk_used_percent
    CPU RDSCourbeAWS/RDS › CPUUtilization
    État des alarmesAlarmesToutes les alarmes du projet
  • 4
    Cliquer sur « Enregistrer le tableau de bord ».
✓ Le tableau de bord est accessible à tout moment depuis la console CloudWatch et offre une vue centralisée de l'état de l'infrastructure Nextcloud.
