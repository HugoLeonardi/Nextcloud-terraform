1. Adresse IP Élastique (Elastic IP)

Par défaut, l'instance EC2 reçoit une adresse IP publique dynamique : elle change à chaque redémarrage. Une Elastic IP est une adresse IPv4 publique fixe allouée sur le compte AWS et attachée à l'instance, garantissant que l'URL Nextcloud reste identique même après un arrêt/relance.

Pourquoi c'est nécessaire Contexte

  • Sans Elastic IP, chaque redémarrage de l'EC2 change l'IP → Nextcloud devient inaccessible.
  • Prérequis indispensable pour configurer un nom de domaine DNS pointant vers le serveur.
  • Prérequis pour un certificat TLS valide (le certificat est lié à un domaine, qui doit pointer vers une IP fixe).

Ressources Terraform à ajouter Code

Deux ressources suffisent : l'allocation de l'EIP et son association à l'instance EC2.

À ajouter dans main.tf
# Alloue une adresse IPv4 publique fixe sur le compte AWS
resource "aws_eip" "nextcloud" {
  domain = "vpc"

  tags = {
    Name    = "${var.project_name}-eip"
    Project = var.project_name
  }
}

# Associe l'EIP à l'instance EC2 Nextcloud
resource "aws_eip_association" "nextcloud" {
  instance_id   = aws_instance.nextcloud.id
  allocation_id = aws_eip.nextcloud.id
}
Modifier outputs.tf pour exposer l'IP fixe
output "nextcloud_url" {
  description = "URL publique fixe de Nextcloud"
  value       = "http://${aws_eip.nextcloud.public_ip}"
}

output "ssh_command" {
  description = "Commande SSH avec l'IP fixe"
  value = "ssh -i ~/.ssh/nextcloud-key.pem ec2-user@${aws_eip.nextcloud.public_ip}"
}

Points d'attention Important

  • Une Elastic IP non associée à une instance est facturée (~0,005 $/heure).
  • La ressource aws_eip_association doit être déclarée après aws_instance — Terraform gère la dépendance automatiquement via la référence aws_instance.nextcloud.id.
  • Le trusted_domains dans Nextcloud devra être mis à jour avec la nouvelle IP fixe (géré via le userdata).

2. Certificat TLS/SSL avec Let's Encrypt

Actuellement, Nextcloud est accessible en HTTP (port 80) : les données transitent en clair. Un certificat TLS permet de passer en HTTPS (port 443), chiffrant les échanges entre le navigateur et le serveur. Let's Encrypt délivre des certificats gratuits et automatiquement renouvelables via l'outil Certbot.

ℹ Un nom de domaine est obligatoire pour obtenir un certificat Let's Encrypt. Let's Encrypt ne délivre pas de certificats pour des adresses IP nues. L'Elastic IP (évolution 1) est donc un prérequis.

Architecture cible Schéma

Internet │ ├── Port 80 (HTTP) ──▶ Redirection automatique vers HTTPS │ └── Port 443 (HTTPS) ──▶ Apache + certificat Let's Encrypt │ ▼ Nextcloud (PHP/Apache) │ ┌─────────┴──────────┐ ▼ ▼ RDS MySQL S3 Bucket (privé VPC) (chiffré AES)

Étapes d'installation Procédure

  • 1
    Ajouter un enregistrement DNS – Créer un enregistrement de type A dans la zone DNS du domaine, pointant vers l'Elastic IP de l'instance EC2. Exemple : nextcloud.mondomaine.fr → 13.37.xx.xx
  • 2
    Ouvrir le port 443 – Ajouter une règle ingress HTTPS au Security Group EC2 (déjà présente dans le code actuel).
  • 3
    Installer Certbot – Via le userdata ou manuellement en SSH sur l'instance.
  • 4
    Émettre le certificat – Certbot communique avec les serveurs Let's Encrypt, prouve la propriété du domaine (challenge HTTP-01), puis configure automatiquement Apache.
  • 5
    Renouvellement automatique – Certbot ajoute une tâche cron qui renouvelle le certificat avant son expiration (durée de vie : 90 jours).

Commandes à intégrer dans userdata.sh Code

# Installation de Certbot et son module Apache
dnf install -y certbot python3-certbot-apache

# Émission du certificat et configuration Apache automatique
# DOMAIN et EMAIL doivent être injectés par Terraform (templatefile)
certbot --apache \
  --non-interactive \
  --agree-tos \
  --email "${admin_email}" \
  --domain "${domain_name}" \
  --redirect    # Force la redirection HTTP → HTTPS

# Activation du renouvellement automatique
systemctl enable --now certbot-renew.timer
Nouvelles variables à ajouter dans variables.tf
variable "domain_name" {
  description = "Nom de domaine pointant vers l'Elastic IP"
  type        = string
  # Exemple : "nextcloud.mondomaine.fr"
}

variable "admin_email" {
  description = "Email pour les notifications Let's Encrypt"
  type        = string
}

Configuration Nextcloud après certificat Code

Nextcloud doit être informé du changement de protocole pour générer des URLs correctes :

# Indiquer à Nextcloud d'utiliser HTTPS
sudo -u apache php occ config:system:set overwriteprotocol \
  --value="https"

# Mettre à jour le trusted_domain avec le nom de domaine
sudo -u apache php occ config:system:set \
  trusted_domains 2 \
  --value="${domain_name}"
⚠ Let's Encrypt impose une limite de 5 certificats par domaine par semaine. En environnement de test, utiliser le flag --staging pour éviter d'atteindre la limite.

3. Supervision avec Amazon CloudWatch

AWS CloudWatch permet de collecter des métriques (CPU, RAM, disque, réseau), de créer des tableaux de bord et de déclencher des alarmes (notification par email, redémarrage automatique…) lorsqu'un seuil est dépassé. L'agent CloudWatch doit être installé sur l'EC2 pour remonter les métriques système (la RAM et le disque ne sont pas collectés nativement par AWS).

Modifications Terraform Code

Ajouter les droits CloudWatch au rôle IAM existant de l'EC2, puis déclarer les alarmes.

1 – Étendre la politique IAM de l'EC2 (main.tf)
resource "aws_iam_role_policy" "ec2_cloudwatch_policy" {
  name = "${var.project_name}-cloudwatch-policy"
  role = aws_iam_role.ec2_s3_role.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Action = [
        "cloudwatch:PutMetricData",
        "cloudwatch:GetMetricStatistics",
        "cloudwatch:ListMetrics",
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents",
        "ec2:DescribeVolumes",
        "ec2:DescribeTags"
      ]
      Resource = "*"
    }]
  })
}
2 – Alarme CPU EC2 (main.tf)
resource "aws_cloudwatch_metric_alarm" "cpu_high" {
  alarm_name          = "${var.project_name}-cpu-high"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 2
  metric_name         = "CPUUtilization"
  namespace           = "AWS/EC2"
  period              = 300   # 5 minutes
  statistic           = "Average"
  threshold           = 80
  alarm_description   = "CPU EC2 dépasse 80% pendant 10 minutes"
  alarm_actions       = [aws_sns_topic.alerts.arn]

  dimensions = {
    InstanceId = aws_instance.nextcloud.id
  }
}

resource "aws_cloudwatch_metric_alarm" "rds_cpu_high" {
  alarm_name          = "${var.project_name}-rds-cpu-high"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 2
  metric_name         = "CPUUtilization"
  namespace           = "AWS/RDS"
  period              = 300
  statistic           = "Average"
  threshold           = 70
  alarm_actions       = [aws_sns_topic.alerts.arn]

  dimensions = {
    DBInstanceIdentifier = aws_db_instance.nextcloud.id
  }
}
3 – Topic SNS pour les notifications par email (main.tf)
resource "aws_sns_topic" "alerts" {
  name = "${var.project_name}-alerts"
}

resource "aws_sns_topic_subscription" "email_alert" {
  topic_arn = aws_sns_topic.alerts.arn
  protocol  = "email"
  endpoint  = var.alert_email
}
4 – Nouvelle variable (variables.tf)
variable "alert_email" {
  description = "Email de réception des alertes CloudWatch"
  type        = string
}

Installation de l'agent CloudWatch sur l'EC2 Code

La RAM et l'espace disque ne sont pas remontés nativement par AWS. L'agent CloudWatch doit être installé via le userdata pour les collecter. 

# Téléchargement et installation de l'agent CloudWatch
dnf install -y amazon-cloudwatch-agent

# Configuration minimale : collecte RAM + disque
cat > /opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json << 'CWCONF'
{
  "metrics": {
    "namespace": "Nextcloud/System",
    "metrics_collected": {
      "mem": {
        "measurement": ["mem_used_percent"],
        "metrics_collection_interval": 60
      },
      "disk": {
        "measurement": ["disk_used_percent"],
        "resources": ["/"],
        "metrics_collection_interval": 60
      }
    }
  },
  "logs": {
    "logs_collected": {
      "files": {
        "collect_list": [{
          "file_path": "/var/log/userdata.log",
          "log_group_name": "/nextcloud/userdata",
          "log_stream_name": "{instance_id}"
        }]
      }
    }
  }
}
CWCONF

# Démarrage de l'agent
/opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config \
  -m ec2 \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json \
  -s

systemctl enable amazon-cloudwatch-agent

Tableau de bord CloudWatch Code

Un dashboard centralisé consultable dans la console AWS.

resource "aws_cloudwatch_dashboard" "nextcloud" {
  dashboard_name = "${var.project_name}-dashboard"

  dashboard_body = jsonencode({
    widgets = [
      {
        type = "metric"
        properties = {
          title  = "CPU EC2"
          period = 300
          metrics = [["AWS/EC2", "CPUUtilization",
                      "InstanceId", aws_instance.nextcloud.id]]
        }
      },
      {
        type = "metric"
        properties = {
          title  = "CPU RDS"
          period = 300
          metrics = [["AWS/RDS", "CPUUtilization",
                      "DBInstanceIdentifier", aws_db_instance.nextcloud.id]]
        }
      }
    ]
  })
}
✓ Après terraform apply, confirmer l'abonnement SNS en cliquant sur le lien reçu par email – sans cette confirmation, les alertes ne sont pas envoyées.
